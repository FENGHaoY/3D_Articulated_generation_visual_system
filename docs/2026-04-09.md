# 基于 SINGAPO 的可视化系统阶段回顾（2026-04-09）

本文档用于回顾当前 `project/` 下 MVP 系统实现情况，梳理目录职责、已完成功能、当前状态与后续优化方向。

## 1. 当前系统目录与职责

### `singapo/`
- 角色：原始 SINGAPO 仓库（模型、权重、推理与相关脚本）。
- 当前接入方式：后端通过适配层调用 `singapo/demo/demo.py`，尽量不侵入核心逻辑。
- 已做最小必要适配：
  - `demo.py` 增加 DINO 本地缓存优先加载逻辑；
  - `demo.py` 在 mesh retrieval 阶段改为使用 `sys.executable` 调用子脚本，避免环境漂移。

### `backend/`
- 角色：FastAPI 后端服务。
- 主要职责：
  - 上传图片、创建任务、查询任务状态；
  - 调用 SINGAPO 推理；
  - 结果整理与统一 manifest 输出；
  - 提供静态文件访问。

关键模块：
- `app/main.py`：应用装配、路由注册、静态目录挂载。
- `app/api/routes_upload.py`：上传接口（含 demo 图上传）。
- `app/api/routes_tasks.py`：任务创建/查询/result 接口。
- `app/api/routes_system.py`：环境自检接口。
- `app/services/singapo_runner.py`：SINGAPO 调用适配层（实时日志、失败处理、产物校验）。
- `app/services/result_organizer.py`：结果整理模块，生成统一 `meta.json`/`result_manifest.json`。
- `app/services/env_check_service.py`：环境诊断（torch、trimesh、依赖导入、关键路径）。
- `app/services/storage_service.py`：任务状态持久化（`runtime/jobs/tasks.json`）。

### `frontend/`
- 角色：**第一版** MVP Web 前端（原生 HTML/CSS/JS + Three.js），保持不动，继续作为稳定对照与离线静态部署选项。
- 主要职责：
  - 图片上传（本地 + demo）；
  - 任务提交与进度显示；
  - 结果清单展示；
  - 3D 模型查看与关节交互。

### `frontend-vue/`
- 角色：**独立目录**的 Vue 3 + Vite + TypeScript 前端，与 `frontend/` **并存**，不覆盖原实现。
- 调用同一套后端 REST 与静态资源约定；开发时通过 Vite 将 `/api`、`/static` 代理到本机 `8000` 端口。
- 主要代码：`src/App.vue`（任务流）、`src/components/ModelViewerPanel.vue`、`src/viewer/MinimalModelViewer.ts`（Three.js，与原版逻辑对齐、单独维护）。

### `runtime/`
- 角色：运行期数据目录。
- 子目录：
  - `runtime/uploads/`：上传图片
  - `runtime/results/`：任务输出目录（每个 `task_id`）
  - `runtime/logs/`：推理日志
  - `runtime/jobs/tasks.json`：任务状态数据库（轻量）

### `scripts/`
- 角色：启动与冒烟脚本。
- 主要脚本：
  - `run_backend.sh`
  - `run_frontend.sh`（静态 `frontend/`）
  - `run_frontend_vue.sh`（Vite 开发 `frontend-vue/`，需本机已安装 Node/npm）
  - `build_pm_demo_catalog.py`（提取 `pm_test` 与 `data` 的映射，产出 Vue 样例库索引与拷贝资产）
  - `run_dev.sh`（一条命令先后台后端、前台静态前端；Ctrl+C 结束两者）
  - `smoke_test.sh`

### `docs/`
- 角色：方案与实现文档。
- 当前新增：本文档（阶段回顾与下一步规划）。

## 2. 已实现功能回顾（MVP 已落地）

## 2.1 端到端链路
- 已打通：上传图像 -> 创建任务 -> 调用 SINGAPO -> 保存结果 -> 前端展示。
- 支持 demo 图一键上传并推理。
- 后端任务状态：`pending / running / succeeded / failed`。

## 2.2 后端接口与静态访问
- 核心接口：
  - `POST /api/upload`
  - `POST /api/upload-demo`
  - `POST /api/tasks`
  - `GET /api/tasks`
  - `GET /api/tasks/{task_id}`
  - `GET /api/task/{task_id}/result`
  - `GET /api/env-check`
- 静态目录：
  - `/static/uploads/...`
  - `/static/results/...`
  - `/static/demo/...`

## 2.3 结果整理标准化
- 每个任务目录生成：
  - `meta.json`
  - `result_manifest.json`
- manifest 至少包含：
  - `task_id`
  - `status`
  - `input_image`
  - `mesh_files`
  - `preview_files`
  - `raw_output_dir`
  - `created_at`
  - `finished_at`
  - 预留：`joints_file`、`parts_file`（当前可空）
- 已对路径做静态 URL 映射，前端可直接访问。

## 2.4 推理稳定性增强
- `OPENAI_API_KEY` 注入（默认 `sk-dummy`），避免 graph 模块导入时直接报错。
- DINO 模型本地缓存优先加载（降低在线依赖）。
- 实时日志输出到后端终端，并同步写入文件。
- 增加 mesh 产物完整性校验（防止“成功但无 part/overall ply”假成功）。
- `env-check` 可快速定位环境缺包/路径错误。

## 2.5 前端可视化与交互
- 页面已重构为左右布局（左：输入与任务，右：可视化交互）。
- 显示总体进度条（粗粒度 0-100）。
- Vue 版新增“样例库 Modal”，按类别展示 `pm_test` 对应视图，可点击样例图直接作为当前输入上传。
- Three.js 最小模型查看可用，支持基础交互：
  - 旋转、缩放、平移（OrbitControls）。
- 支持关节参数交互（基于 `object.json`）：
  - 可动关节 panel + slider；
  - 点击部件高亮；
  - 显示 joint axis（ArrowHelper）；
  - 一键复位姿态；
  - 模型自动贴地显示（避免网格穿模）。
- 全屏查看按钮已实现（原生 Fullscreen + 回退模式）。

## 3. 当前实现状态评估

## 3.1 已达到
- MVP 基本目标已达成：能跑通推理并可交互查看可动结果。
- 系统结构清晰，前后端与原始 `singapo` 分离。
- 具备调试与可运维性（日志、环境检查、状态查询）。

## 3.2 当前边界
- 前端仍是原生 JS，文件单体较大，维护成本开始上升。
- 关节交互是 MVP 级实现，尚非完整 URDF 语义与物理约束。
- 结果格式仍偏 SINGAPO 原始产物，缺统一“可动资产标准”。
- 后端任务执行为单机线程模型，尚未队列化/并发治理。

## 4. 后续优化建议（按优先级）

## 4.1 前端方向
- **框架升级（高优先级）**
  - 已在 `frontend-vue/` 落地 **Vue 3 + Vite + TypeScript** 独立工程，**不替换** `frontend/`。
  - 后续在此目录继续拆分模块：上传区、任务区、Viewer、JointPanel、ResultPanel；按需引入 Pinia、组件库等。
  - 优点：状态管理更清晰、可维护性和扩展性显著提升。

- **UI/交互美观优化**
  - 统一设计系统（色板、间距、阴影、排版层级）。
  - 增加空态/加载态/失败态组件。
  - 增加“任务时间线”与“推理阶段标签”。

- **更多输入来源（重点）**
  - 在前端增加示例集浏览器，使用已预测图连接结果做展示输入：
    - `singapo/exps/pred_graph/pred_graph/pm_test`
    - 以及其他 `pred_graph` 子集。
  - 按 `dataset -> category -> model_id -> view` 组织可选样本。
  - 用户点击样本图后自动触发“上传 + 携带元信息”。

## 4.2 可动三维表达方向
- 建议新增中间标准：
  - `articulation.json`（links/joints/limits/axes/mesh mapping）
  - 使前端可直接按统一语义装载，不依赖零散路径约定。
- 后续可支持：
  - 关节联动规则；
  - 更完整的 revolute/prismatic 可视化约束；
  - 接近 URDF viewer 的控制体验（树状关节、关节组控制）。

## 4.3 后端方向
- **任务系统增强**
  - 迁移到异步队列（Celery + Redis 或 RQ），避免长任务阻塞。
  - 任务日志与状态改用结构化存储（SQLite/PostgreSQL）。

- **结果与资产管理**
  - 增加结果版本与清理策略（按日期/任务状态）。
  - 统一错误码和失败原因分层（环境错误/模型错误/资产缺失）。

- **可观测性**
  - 增加 metrics（任务耗时、失败率、阶段耗时）。
  - 增加健康检查与依赖状态监控（GPU、磁盘、模型缓存）。

## 4.4 工程化与部署
- 增加自动化测试：
  - 后端 API 测试；
  - 前端关键交互 E2E。
- 增加 CI（lint + basic smoke）。
- 未来可容器化部署（分离 backend / worker / static）。

## 6. 结论

当前系统已经完成第一阶段 MVP：可上传、可推理、可查看、可交互，且整体结构清晰，满足“最小可用 + 少侵入 SINGAPO”的目标。

## 7. 当前系统启动命令（终端直接执行）

以下命令默认在项目根目录执行：`/root/rivermind-data/project`

### 7.1 启动后端

```bash
cd /root/rivermind-data/project
bash scripts/run_backend.sh
```

可选：指定端口（例如 8001）：

```bash
cd /root/rivermind-data/project
bash scripts/run_backend.sh 8001
```

### 7.2 启动前端

```bash
cd /root/rivermind-data/project
bash scripts/run_frontend.sh
```

可选：指定端口（例如 8081）：

```bash
cd /root/rivermind-data/project
bash scripts/run_frontend.sh 8081
```

### 7.2.1 启动 Vue 版前端（`frontend-vue/`，与 `frontend/` 并存）

需本机已安装 Node.js / npm（若仅有 Conda：`conda install -y -c conda-forge nodejs=20`）。请先启动后端（默认 `8000`），Vite 会将 `/api` 与 `/static` 代理到 `http://127.0.0.1:8000`。

```bash
cd /root/rivermind-data/project
bash scripts/run_frontend_vue.sh
```

浏览器访问：`http://127.0.0.1:5173`。自定义端口示例：`bash scripts/run_frontend_vue.sh 5174`。

### 7.3 一键冒烟检查（可选）

```bash
cd /root/rivermind-data/project
bash scripts/smoke_test.sh
```

### 7.4 访问地址（默认端口）

- 静态前端（`run_frontend.sh`，脚本默认端口以 `scripts/run_frontend.sh` 为准）：常见为 `8080` 或 `8081`
- Vue 开发前端：`http://127.0.0.1:5173`
- 后端 API：`http://127.0.0.1:8000`
- 后端文档：`http://127.0.0.1:8000/docs`

### 7.5 一条命令同时启动前后端（推荐本地开发）

在项目根目录执行；会先后台拉起后端，待端口可连后再前台启动静态前端；**在前端终端按 Ctrl+C 会一并结束后端进程**。

```bash
cd /root/rivermind-data/project
bash scripts/run_dev.sh
```

可选：依次指定「后端端口」「前端端口」（与单独启动脚本一致）：

```bash
cd /root/rivermind-data/project
bash scripts/run_dev.sh 8001 8081
```

### 7.6 常见运行顺序建议

1. 日常可一条命令：`bash scripts/run_dev.sh`；或分两个终端分别跑 `run_backend.sh` / `run_frontend.sh`。  
2. 打开前端页面后，先点一次 demo 上传测试链路。  
3. 若任务失败，优先查看：`runtime/logs/<task_id>.log`。
