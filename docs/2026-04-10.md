## 3. `frontend-vue/` 详细路径职责（重点）

以下为当前 `frontend-vue/` 关键路径及作用说明（按使用频率与功能分组）：

## 3.1 工程与构建层
- `frontend-vue/package.json`
  - Vue/Vite/TS/Three 依赖与脚本入口（`dev/build/preview`）。
- `frontend-vue/package-lock.json`
  - npm 锁定文件，保证安装一致性。
- `frontend-vue/vite.config.ts`
  - Vite 开发配置；
  - 将 `/api`、`/static` 代理到后端 `127.0.0.1:8000`。
- `frontend-vue/tsconfig.json`
  - TS 工程总入口（references）。
- `frontend-vue/tsconfig.app.json`
  - 应用侧 TS 编译选项。
- `frontend-vue/tsconfig.node.json`
  - Node/Vite 配置文件侧 TS 编译选项。
- `frontend-vue/index.html`
  - Vite 挂载页，加载 `src/main.ts`。
- `frontend-vue/src/vite-env.d.ts`
  - Vite 环境变量类型定义（如 `VITE_API_BASE`）。
- `frontend-vue/README.md`
  - Vue 前端使用说明、依赖、运行方式。

## 3.2 页面与业务入口层

## 6. 接口字段对照表（前端 -> 后端 -> 推理）

## 6.1 上传链路
- 前端：`uploadFile(file)` / `uploadDemo()`
  - 路径：`frontend-vue/src/api/client.ts`
- 后端接口：`POST /api/upload`、`POST /api/upload-demo`
  - 返回关键字段：`upload_id`、`file_url`
- 用途：
  - `upload_id` 作为后续 `POST /api/tasks` 的主关联键。

## 6.2 任务创建链路（含样例 graph 绑定）
- 前端请求体（`createTask`）：
  - `upload_id`（必选）
  - `n_samples=1`（当前固定）
  - `demo_sample_id`（可选；如 `Dishwasher@12414@18`）
- 后端模型：
  - `CreateTaskRequest.upload_id`
  - `CreateTaskRequest.demo_sample_id`
- 后端处理：
  - `TaskService._resolve_demo_graph_path()` 将 `demo_sample_id`
    映射到 `singapo/exps/pred_graph/pred_graph/pm_test/<id>.json`
  - 路径不合法或不存在时返回 `400`
- 推理命令层（`SingapoRunner`）：
  - 传入 `--pred_graph_path <mapped_json>`
  - `demo.py` 优先级：`pred_graph_path > use_example_graph > GPT预测`

## 6.3 任务查询与结果展示链路
- 前端轮询：
  - `GET /api/tasks/{task_id}`（状态、进度）
- 前端结果：
  - `GET /api/task/{task_id}/result`
- 结果清单关键字段（示例）：
  - `task_id`、`status`
  - `input_image`
  - `mesh_files`
  - `preview_files`
  - `object_json_files`
  - `created_at`、`finished_at`

## 7. 结合 2026-04-09 的后续改进方向（更新版）

以下内容结合 `docs/2026-04-09.md` 中 4.1~4.4 的规划，并按“可落地优先级”重排：

## 7.1 前端方向（Vue 主线）
- **模块化深化（高优先级）**
  - 将 `App.vue` 进一步拆分：`DemoLibraryCard`、`TaskStatusPanel`、`ResultPanel`、`UploadActions`；
  - 引入统一状态管理（可选 Pinia），避免跨组件状态分散。
- **UI/交互体验提升**
  - 建立统一 Design Tokens（色板、阴影、间距、字号）；
  - 增加空态/加载态/错误态组件；
  - 样例库增加筛选与搜索（category/model_id/view）。
- **输入来源扩展**
  - 在 `pm_test` 之外，支持更多 `pred_graph` 子集；
  - 支持按 `dataset -> category -> model_id -> view` 逐级筛选。

## 7.2 可动三维表达方向
- 建议引入标准中间层：`articulation.json`
  - 统一 links/joints/limits/axes/mesh mapping；
  - 让前端不再依赖散落路径约定。
- 逐步增强关节交互：
  - 关节联动规则；
  - revolute/prismatic 约束可视化；
  - 更接近 URDF viewer 的控制体验（树状层级/关节组）。

## 7.3 后端方向
- **任务系统增强**
  - 从线程模型迁移到队列模型（Celery + Redis / RQ）；
  - 降低长任务阻塞风险并支持更稳健调度。
- **存储与可观测性**
  - 任务状态与日志结构化（SQLite/PostgreSQL）；
  - 增加指标：耗时、失败率、阶段耗时；
  - 增加健康检查：GPU/磁盘/模型缓存状态。
- **结果资产治理**
  - 结果版本化；
  - 清理策略（按日期、状态、保留期）；
  - 错误码分层（环境错误 / 模型错误 / 资产缺失）。

## 7.4 工程化与部署
- 测试：
  - 后端 API 自动化测试；
  - 前端关键链路 E2E（上传、选样例、推理、结果展示）。
- CI：
  - lint + basic smoke（前后端）。
- 部署：
  - 逐步容器化（backend / worker / static 分离）。
